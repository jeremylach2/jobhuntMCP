# AGENTS.md

Orientation for agents working in this repo. Read `README.md` for what the
project *is*. This file covers what you need to know to change it safely.

## What this is

An MCP server (and CLI) that pulls job postings from public ATS endpoints,
triages them, and tracks assessments and application state in local SQLite.
Personal tool for one user's job search. Optimize for correctness and
legibility over generality.

## Layout

```
src/jobhunt/
  models.py      Job dataclass, HTML->text, remote detection
  db.py          SQLite store: jobs, fit, applications, events, company_notes
  config.py      Loads profile/targets.yaml + env path overrides
  scoring.py     Keyword PREFILTER + triage() dedup. Not an evaluator.
  sync.py        Orchestrates sources -> store
  server.py      MCP server (14 tools, the primary interface)
  cli.py         argparse CLI (the same data, for cron/scripting)
  sources/       One adapter per board. Each exposes async sync()
profile/
  targets.yaml   Watched company slugs + keywords + preferences (GITIGNORED, never commit)
  targets.example.yaml  Public template
  resume.md      Real resume (GITIGNORED, never commit)
  resume.example.md  Public template
  tailored/      Per-posting tailored resumes (GITIGNORED, generated by the
                 tailor-resume skill, never commit)
.claude/skills/
  tailor-resume/ Rewrites resume.md for one job posting without inventing
                 content (see that SKILL.md for the rules)
```

## The one design rule

**`scoring.py` must never try to decide whether a job is a good fit.** It is a
cheap prefilter that answers only "is this plausibly the right family of role",
so that a model isn't asked to read 12,000 postings to find the 40 that matter.
Real judgment happens in the model and is persisted via the `record_fit` tool
into the `fit` table.

If you find yourself adding "does this match the user's background" logic to
Python, that belongs in the model instead. Adding more regex rules to
`scoring.py` is almost always the wrong fix.

Corollary: keep tool outputs bounded. `search_jobs` returns one line per
posting. Only `get_job` returns a full description. Don't make a list-shaped
tool return descriptions. It blows up context for no benefit.

Corollary: that boundedness should hold at the database layer too, not just
in what gets rendered to text. `store.search()` takes a `description_limit`
so a bulk caller that only needs metadata (`search_jobs`) or a keyword prefix
(`shortlist_for_review`, via `scoring.relevance`) isn't handed every unscored
posting's full text out of SQLite just to discard most of it. Pass it
whenever a new list-shaped tool doesn't render `row["description"]`.

Corollary: company reputation (WLB, culture, stability) is on-demand, never
automatic. There is no free, unauthenticated API for it, so `company_notes`
is a cache the model fills by hand, not a fetched source: `get_job` surfaces
whatever is already cached for a posting's company, but does *not* prompt
research when the cache is empty. Doing that on every `get_job` call would
mean a web search per posting, against the whole point of a cache. Research
happens only when the user (or the model, if asked) explicitly wants it: its
own web search, then `add_company_notes` to persist findings. Don't try to
build a scraper for this. The same reasoning as the LinkedIn/Indeed rule below
applies to Glassdoor/Comparably.

## Invariants worth not breaking

- **`Job.id` = sha256(source + source_id)[:16].** Changing this orphans every
  stored fit assessment and application record. Don't.
- **`store.search(limit=0)` means unlimited.** The triage path depends on it. A
  default cap there silently hides most of the corpus. This was a real bug.
- **`first_seen` is preserved on upsert.** It's how "what's new" works.
- **`deactivate_missing` is scoped to boards actually fetched.** A failed sync
  must never retire postings from a board it couldn't reach.
- **Adapters never raise on one bad board.** A wrong slug among 90 companies
  gets collected into `SourceResult.errors`, not propagated.

## Working with the sources

All five endpoints are public and unauthenticated: no keys, no scraping, no
browser. Fetch serially with ~1s delay. Don't parallelize a free endpoint.

| Source | Notes |
|---|---|
| Greenhouse | `?content=true` returns descriptions inline (one request per board) |
| Ashby | Richest: plain text + `isRemote` + salary bands. Use the `posting-api`, **not** the GraphQL endpoint |
| Lever | Returns `{"ok": false}` with HTTP 200 for a bad slug, so check the shape, not the status |
| Himalayas | Whole remote market, keyword-filtered locally or it floods the DB |
| HN | Free-form comment text. Deliberately barely parsed. Let the model read it |

**Never add LinkedIn or Indeed.** Both prohibit automated access in their terms
and actively block it. That part of the search stays manual, by decision. The
same applies to Glassdoor/Comparably for company-review scraping. See the
`company_notes` corollary above for how that's handled instead.

**Verify slugs before adding them to `targets.yaml`.** Every slug in there was
probed against the live endpoint first. Guessed slugs fail silently-ish (they
show up under `errors` in the sync report, which is easy to skim past).

```bash
curl -s "https://boards-api.greenhouse.io/v1/boards/SLUG/jobs" | head -c 200
curl -s "https://api.ashbyhq.com/posting-api/job-board/SLUG" | head -c 200
curl -s "https://api.lever.co/v0/postings/SLUG?mode=json" | head -c 200
```

## Commands

```bash
uv pip install -e ".[dev]"
pytest                    # 35 offline tests
pytest -m live            # hits real endpoints, run when touching sources/
jobhunt sync              # ~93 boards, a couple of minutes
jobhunt shortlist --limit 25
```

MCP server is registered locally as `jobhunt`. After changing `server.py`,
restart Claude Code to pick it up. Verify a change over the real protocol
rather than only importing the module. Tool registration and schema generation
only fail at handshake time.

## Environment notes

- Windows. Use the Bash tool for POSIX. Large heredocs through it are unreliable
  for multi-hundred-line files. Use the Write tool instead.
- The venv has no `pip`. Use `uv pip install`.
- `mcp` is **2.x**, where `FastMCP` was renamed `MCPServer`
  (`from mcp.server.mcpserver import MCPServer`). Don't follow 1.x examples.
- CLI reconfigures stdout to UTF-8. Salary strings contain en-dashes that the
  default Windows codepage mangles.

## Don't

- Commit `profile/resume.md`, `profile/targets.yaml`, or `jobhunt.db` (all
  gitignored, keep it that way).
- Add application auto-submission. Out of scope by decision: ATS forms vary too
  much to be reliable, and nothing should be sent under the user's name that
  they haven't read.
